# 집노트 · JIPNOTE

서울·경기 아파트 매매를 예산, 직장 위치, 선택적 제외지역으로 비교하는 Next.js 애플리케이션입니다. UI와 서버 API를 한 프로젝트에서 실행합니다.

## 실행

Node.js 22 이상과 npm이 필요합니다. 설치 버전은 `package-lock.json`에 고정되어 있습니다.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

[로컬 사이트 열기](http://127.0.0.1:3000)

첫 화면에는 분석 실행 안내만 표시합니다. **가상 가격·예시 단지는 표시하지 않습니다.** API 키가 없으면 실행 버튼을 비활성화하고 연결 방법을 안내합니다. 실제 분석이 성공하면 가격과 출처를 표시하며, 실패하면 오류와 재시도 버튼을 보여줍니다.

### 실시간 분석 연결

`.env.local`에 다음 값을 설정하고 서버를 재시작하세요.

```dotenv
OPENAI_API_KEY=발급받은_API_키
OPENAI_MODEL=gpt-5.4-nano
DATA_DIR=./.data
```

- `OPENAI_API_KEY`: Responses API, 웹 검색을 사용할 수 있는 서버 전용 키. `NEXT_PUBLIC_` 환경변수에 넣지 않습니다.
- `OPENAI_MODEL`: 계정에서 사용할 수 있고 `web_search` 및 Structured Outputs를 지원하는 모델로 변경 가능.
- `DATA_DIR`: 리포트 영속 저장 위치. 기본 `.data`, 사용자별 최근 30개.

분석은 지역별 후보 발굴 3회와 단지별 가격 검색 최대 8회로 구성되며 API 비용이 발생합니다. 재시도 제외 최대 11회이며 순차 실행합니다. 실제 서비스 계정의 API 모델 권한·쿼터를 확인하세요. 분석이 수 분 걸릴 수 있어 진행 상태를 스트림으로 표시하며 중단할 수 있습니다.

## 기본 조건

| 항목 | 기본값 | 변경 |
| --- | --- | --- |
| 예산 | 9억~11억원 | 필수 입력 |
| 직장/목적지 | 판교역, 서울대입구역 | 필수 입력, 쉼표로 최대 3곳 |
| 제외지역 | 없음 | 선택, 시·구·동 이름 |
| 주택 유형 | 아파트 매매 | 고정 |
| 최소 면적 | 전용 59㎡ | 고급 조건에서 변경 |
| 통근 | 목적지 중 한 곳까지 약 60분 안팎 | 고급 조건에서 변경 |
| 평가 | 실거주 + 중장기 투자성 | 기본 분석 지침 |

기존 프롬프트의 노원·서울 북부·경기 북부 제외 조건을 하드코딩하지 않았습니다. 원하는 제외지역을 직접 입력합니다. 모델에 하위 행정구역과 별칭을 해석하도록 지시하고, 서버에서 주소/지역 문자열을 추가 검증합니다. `서울 북쪽 끝`처럼 경계가 불명확한 표현 대신 `노원구, 도봉구, 은평구 불광동`처럼 행정구역을 사용하는 것이 좋습니다. 법정동 코드 기반 지오코딩 검증은 아직 연결하지 않았습니다.

통근 기준은 절대 필터가 아닌 평가 항목입니다. 여러 직장은 대안 목적지로 해석합니다. 직장 입력은 실시간 조사에 반영되며, 검색에서 경로를 확인하지 못하면 통근시간을 확정하지 않습니다.

## 구현 기능

- 반응형 대시보드와 조건 입력 모달
- 서울·경기 통합 비교표, 지역 필터, 단지명 검색, 투자성/실거주성/가격 정렬
- 거래 흐름과 현재 호가를 분리한 상세 화면, 출처 링크, 리스크
- 단지명·면적·최근 실거래가·계약일/층·매매 호가·확인일·출처를 우선하는 가격 비교표. 모바일은 가격을 나란히 보여주는 단지 카드. 지역 온도표·일반 뉴스·시장 요약은 표시하거나 생성하지 않음
- 전용 로딩 화면(검색·가격 비교 두 단계·경과 시간·중단·완료 시 자동 전환), API 키 누락/권한/요청 제한/부분 검색 실패 처리
- HttpOnly 개인 식별 쿠키로 구분한 리포트 보관함, 원자적 파일 저장, JSON 내보내기
- 회원가입·로그인 없이 로컬스토리지에 관심단지의 정보·출처·기준일 저장/삭제. 검색 조건과 리포트가 바뀌어도 유지되며 다른 탭의 변경도 반영합니다. 최대 100개, 저장 당시 정보이며 자동 갱신되지 않습니다.
- 결과 상단에 AI 분석·신고 지연 등에 따른 부정확성 안내
- 실시간 출처 URL 대조, 필수 가격 출처, 날짜 유효성·미래 거래 차단, 예산·면적·제외지역 검증
- 최근 100일 실거래와 최근 14일 내 확인 호가만 후보 선정에 사용
- 같은 전용면적의 연속 확인 거래가 ±3% 또는 ±0.5억원 이상 변하면 별도 표시. 같은 날짜의 두 건은 시간 변화로 판단하지 않음
- 동일 조건의 이전 저장 리포트를 다음 분석에 제공. 검색은 이전 후보에 국한하지 않고 매번 새로 수행

## 서버 구조

```text
Browser (React client)
  ├─ GET /api/config                 연결 상태만 확인
  ├─ GET /api/reports                개인 저장 이력
  └─ POST /api/reports (JSON → SSE)
       ├─ 동일 출처·입력값·동시 실행 검증
       ├─ 지역별 후보 발굴 3회 (단지명·주소·상세 출처 확보)
       │   ├─ 서울 25개 구
       │   ├─ 경기 남부·동남부
       │   ├─ 경기 서부·기타
       │   └─ 매매 가격 교차 확인
       ├─ 중복·제외지역 제거 후 최대 8개 단지별 가격 추가 검색
       ├─ 출처·날짜·조건 필터, 가격 변화 계산
       └─ DATA_DIR/{session UUID}.json 저장
```

별도 Express/FastAPI 서버는 필요 없습니다. `app/api`의 Route Handlers가 서버 역할을 합니다. 검색 지침은 `lib/prompt.ts`, 입력/리포트 계약은 `lib/schema.ts`, 데이터 검증은 `lib/validation.ts`, 검색 어댑터는 `lib/research.ts`에 분리되어 있습니다.

### API

`POST /api/reports`

```json
{
  "minBudget": 9,
  "maxBudget": 11,
  "workplaces": ["판교역", "서울대입구역"],
  "excludedRegions": [],
  "minArea": 59,
  "commuteMinutes": 60
}
```

예산은 억원입니다. `Content-Type: application/json`을 사용합니다. 회원가입·로그인·접근 암호는 필요 없습니다. 스트림 이벤트는 `progress`, `heartbeat`, `result`, `error`입니다. 스트림 시작 전 실패는 JSON + 4xx/5xx로 반환합니다. 검색이 모두 실패하면 성공 리포트를 만들지 않고 오류를 반환합니다. 일부 실패는 coverage와 limitations에 표시합니다. 제한 시간은 570초입니다.

## 데이터 정확성의 현재 범위

**현재 구현은 공개 웹 검색 기반 리서치입니다.** 국토교통부 거래 원장 API, 유료 매물 DB, 실시간 길찾기 API를 직접 연동한 전수 스캔 엔진은 아닙니다.

- 국토부 자료를 최우선으로 조사하도록 지시하되 페이지에 접근할 수 없으면 확인했다고 표시하지 않습니다.
- 실제 웹 검색 도구가 반환한 URL 목록과 모델의 출처를 대조합니다. URL이 실제 열람 목록에 있다고 해서 원문의 숫자와 모델 해석까지 자동 검증되었다는 뜻은 아닙니다. 원문 확인은 필요합니다.
- 네이버/호갱노노 등의 비공개·로그인·동적 페이지는 검색으로 얻지 못할 수 있습니다. 호가가 없으면 `미확인`. 실거래만 있는 후보는 현재 매물 가격 보장이 아닙니다.
- 호가 범위가 예산과 겹치는 후보를 포함합니다. 범위 일부는 예산을 초과할 수 있습니다.
- 현재 가격 변화 섹션은 확인된 동일 면적 실거래의 직전 건 비교입니다. 전일 호가 스냅샷, 신고가/신저가의 전체 이력 검증, 거래량 급증의 정량 탐지는 별도 시계열 수집기가 필요합니다.
- 정성 점수는 확정 수익률 또는 공인 통계가 아닙니다. 공급·학군·전세·사업 진행 정보의 누락은 리포트에 표시하도록 지시합니다.
- 쿠키 삭제/다른 브라우저 사용 시 기존 개인 보관함과 연결되지 않습니다. 회원 계정·계정 복구는 없습니다.
- **자동 일일 실행·이메일/푸시 발송은 이 버전에 포함하지 않았습니다.** 사용자의 현재 요청에 맞춰 버튼으로 실행하는 사이트로 구현했습니다.

## 운영 및 확장

단일 Node 프로세스 + 영속 디스크를 전제로 합니다. 프로덕션 실행:

```sh
npm run build
npm start
```

외부 배포 시 HTTPS 뒤에서 서비스하고, 리버스 프록시의 스트리밍 버퍼링을 끄고 타임아웃을 600초 이상으로 설정합니다. 세션 쿠키는 프로덕션에서 Secure입니다. 네트워크 전용 키와 리포트 파일은 public 디렉터리에 두지 않습니다.

인메모리 제한: 동시 2건, 세션별 동시 1건, 세션당 시간당 6회, 프로세스 전체 시간당 20회. 재시작 시 초기화됩니다. 회원 인증 없이 실행할 수 있습니다. 개인 리포트 구분에는 익명 HttpOnly 쿠키를 사용하고 관심단지는 로컬스토리지에만 저장합니다.

서버리스/다중 인스턴스/자동 데일리 운영으로 확장할 때:

1. 파일 저장소를 PostgreSQL로 교체: 사용자, 검색조건, 리포트, 관심단지, 실거래/호가 스냅샷 테이블.
2. Redis 기반 작업 큐·분산 요청 제한, 별도 리서치 워커. 긴 검색은 HTTP 요청과 분리.
3. 국토부 아파트 매매 실거래 API 키로 시군구 코드·월별 원장을 수집. 취소/정정/중복을 다루고 법정동 코드를 정규화.
4. 라이선스가 허용되는 호가 제공처와 통근 길찾기 제공처 연동. 거래·호가·경로 확인시각 저장.
5. 계정 인증, 사용자별 스케줄/Asia-Seoul 타임존, 매일 실행 작업, 이메일/웹 푸시 알림 어댑터 추가.

현재 파일 저장 방식을 Vercel 같은 임시 파일 시스템에 그대로 배포하면 영속 보관을 보장하지 못합니다.

## 검증

```sh
npm test
npm run lint
npm run typecheck
npm run build
npm run test:e2e
```

E2E는 설치된 Google Chrome을 사용합니다. 없는 환경에서는 `npx playwright install chromium`을 실행하고 `playwright.config.ts`의 `channel: "chrome"`을 제거하세요.

조건·가격 변화·출처 제거·저장소 격리 테스트와 데스크톱/모바일 UI·API 테스트를 포함합니다. E2E의 실시간 결과는 명시적으로 모킹하며 유료 API를 호출하지 않습니다. 최근 확인에서 같은 키의 짧은 요청은 정상 완료되었고, `gpt-5.4-mini`의 실제 웹 검색 1건도 출처를 포함해 약 8초에 완료됐습니다. 전체 부동산 분석의 지연 시간과 품질을 보장하는 수치는 아닙니다. 429는 결제 한도·요청/토큰 속도 제한을 구분해 안내합니다.

- [OpenAI 웹 검색](https://developers.openai.com/api/docs/guides/tools-web-search): 검색 도구와 실제 검색 출처 목록
- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): Zod 기반 출력 구조 검증

### API 크레딧 부족 오류

`credit_balance_exhausted` 또는 `insufficient_quota`가 발생하면 [OpenAI Billing](https://platform.openai.com/settings/organization/billing/overview)에서 API 결제·크레딧·사용 한도를 확인하세요. 실패한 분석은 가상 결과로 대체하지 않습니다. 테스트의 가상 자료는 `tests/fixtures/`에만 있으며 사이트에서 불러오지 않습니다.

### 처리량 제한과 모델

후보 발굴은 `gpt-5.4-mini`(추론 low), 가격 수집은 `gpt-5.4-nano`(추론 none), 검색 컨텍스트는 `low`입니다. 후보 발굴 3회(각 출력 상한 3,500)와 최대 8개 단지의 가격 수집(각 출력 상한 3,000)을 순차 실행합니다. 최종 예산 필터·정렬·가격 변화 계산은 서버가 수행하며 별도 GPT 요청을 하지 않습니다. 재시도 제외 최대 11회입니다. 실제 토큰 사용량은 각 응답마다 기록합니다. 일부 수집 실패 시 확인된 후보는 유지하되, 가격 확보가 전부 실패하면 빈 성공 리포트를 저장하지 않습니다. 계정 오류 및 재시도 후 429는 후속 요청을 중단하며 전체 실행은 기존 570초 제한을 따릅니다. 화면에는 검색 중/가격 비교 진행 중만 표시합니다.

## 개별 호가와 참고시세 구분

수집 응답의 `listings`는 전용면적·확인일·출처가 있는 개별 매물이며, 서버가 유효한 목록에서 호가 범위를 계산합니다. `referencePrices`의 매물평균가·KB시세·집계최저가는 개별 호가로 사용하지 않습니다. 개별 호가 확인 후보를 먼저 정렬하고, 실거래만 확인된 후보는 현재 호가 확인 필요로 유지합니다. 참고시세만 있는 단지는 별도 `referenceCandidates`에 저장하여 시세 참고 단지 목록에 표시합니다. 실제 호가가 예산을 넘으면 과거 거래가나 평균가로 예산 내 매물을 주장하지 않습니다. 날짜·면적·제외지역·출처 검증은 유지됩니다.

이 변경은 오프라인 회귀 테스트와 모의 API 화면 테스트로 확인했습니다. 사용자가 전달한 단지 가격은 테스트 전용이며 운영 데이터로 삽입하지 않았습니다.

### 가격 단위 계약

가격 추출 API는 trades/listings/referencePrices 각각에 `unit`(원/만원/억원)을 반드시 반환합니다. 서버가 이를 억원으로 환산한 뒤 예산을 비교합니다. 단위 없는 과거 응답은 숫자 크기만 보고 자동 환산하지 않습니다. 후보 발굴도 priceHint에 단위 포함 가격을 받아, 이미 예산 밖으로 확인된 후보가 개별 조회 비용을 쓰지 않도록 합니다. 면적 0은 실제 면적으로 보완하거나 추측하지 않습니다.

2026-09-15 저장 응답 조사에서 원 단위 숫자를 억원으로 비교한 오류와 실제 개별 호가 수집 부재를 확인했습니다. 단위 처리 수정의 테스트 통과는 검색 품질 검증을 대체하지 않습니다.
